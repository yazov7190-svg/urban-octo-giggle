# Cooler cities：兰州降温设施选址与方案比较

在线平台：https://yazov7190-svg.github.io/urban-octo-giggle/

选择街道，在真实人口地图上比较A/B/C候选点、自选D点和双点布局；调整措施包、服务半径、预算、到场比例、容量及故障，获取覆盖、费用和服务缺口比较。支持导出JSON、CSV、打印和情景链接分享。代码由main分支根目录通过GitHub Pages发布。

## 已接入的数据

- 50个街道边界、107个公园要素，及区域内OSM建筑、道路和水体。
- 团队提供的2025年人口栅格 `chn_pop_2025_CN_100m_R2025A_v1.tif`。3角秒，名义约100米，值按估计人/像元解释，文件名与WorldPop Global2产品对应。不是人口普查实测或实时人流。按像元中心归属街道，共29,170个正值人口网格，未发现中心重复归属。四舍五入后可能存在极小零值。50街道合计约2,868,530人，仅代表本数据与边界组合结果。
- ERA5-Land 2000-01-01至2025-12-31，312个月文件、9,497天，变量t2m，源单位K，转换为℃。元数据记录UTC+8日界。网格0.1°；对街道与网格交叠面积加权，求每日最高温的街道平均，再统计各年最高值、夏季日最高温均值和≥30/32/35℃日数。50街道每年记录完整。

人口文件的2015—2030年版本已在本地发现，本次上线选用与温度末年一致的2025年。选择2000—2025年只切换热背景，人口始终是2025年估计。2026年及以后人口不作为实测使用。

## 决策逻辑与边界

1. 自动候选点来自公园内部与高人口网格附近，排除已有建筑、水体，距已绘道路不超过150米；按300米覆盖人口初筛、保持180米间距，每街道3个。这是有限候选集，不保证全局最优，也不代表具备施工许可。改变半径后只重新比较既有候选点。
2. 网页按球面距离统计半径内、本街道内的居民估计，重叠范围去重。服务圆不是降温范围，也不是步行路网可达范围。
3. 单时段需求＝估计居民×用户设置的到场比例。将范围内需求分配到最近的开放点，每点服务量受容量上限约束。未服务需求包括范围外需求与点位容量不足；不模拟排队、跨时段停留、跨河阻隔或满载后的二次转移。
4. 相同措施包按建设点数计费，故障点仍计建设成本。费用含建设、运行维护与评价期内更换折现，不计残值。原型单价、到场比例、容量是情景假设，来源于data.js，不能当作工程报价或实测需求。
5. 建设预算内，按服务缺口最小、覆盖人口最多、评价期费用最低排序，给出踏勘建议。温度不自动决定到场比例；同街道候选点共用粗尺度热背景，不编造100米点位温差。没有设施降温模拟结果，不报告改造降低几℃。

## 演示

默认张掖路街道、2025年热背景、300米半径、到场比例1%、每点容量60人、遮阳措施包、5万元预算。A点约覆盖9,853居民；B+C约覆盖14,821居民，覆盖去重。默认示例建设费分别2万元、4万元；这些人口是范围内居民，不是同一时段获服务人数。
